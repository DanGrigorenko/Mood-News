# Verdict — одно определение «как прошла попытка»

Вопрос «прошла ли попытка переписывания» имеет **одно** определение на весь
pipeline — module `Verdict` (`server/src/verdict.ts`). Три потребителя читают его,
а не поля Rewrite напрямую:

- **ранжирование** попыток — `betterVerdict` (какой из двух вердиктов лучше);
- **выход из ретрай-цикла** — `accepted` (годен ли вердикт, ретраить ли);
- **решение о кэше** — `fitForCache` (годится ли вердикт для записи, docs/adr/0008).

Вход вердикта — то, что о попытке известно после сверок: список Missing Anchor,
мера непохожести на Snippet (`similarity`), исход Meaning Check и найденный
Distortion. `verdictOf` — единственное место, где `similarity` превращается в
`unchanged` по порогу `UNCHANGED_SIMILARITY_THRESHOLD` (порог переехал в этот
module: граница «копия / переписано» — часть вердикта).

Ретрай-цикл сохраняет счётчик попыток и `MAX_ATTEMPTS`, но правил приёмки внутри
себя больше не держит: он читается как последовательность шагов
(сгенерировать → сверки → Meaning Check по гейту `anchorsPassed` → `accepted`?).

## Почему

Раньше на «как прошла попытка» отвечали три независимых чтения одних и тех же
полей: `rank`/`better`, условие `if (missing.length > 0 || unchanged) continue`
плюс ветки Meaning Check, и `passedBothChecks`. На `meaningCheck: 'skipped'` они
согласовывались только на глаз, и чтобы понять, почему конкретный Rewrite не попал
в кэш, нужно было прочитать три предиката и заметить, что они расходятся.

Теперь расхождение — **явное свойство** вердикта, а не побочный эффект трёх мест.
`accepted` и `fitForCache` расходятся ровно на `skipped`:

- `accepted(skipped) = true` — из цикла выходим (сверка честно «не проверено», а
  не провал, запрос не роняем);
- `fitForCache(skipped) = false` — в кэш не пишем (непроверенный Rewrite не должен
  стать вечным свойством новости, docs/adr/0001).

`fitForCache` строже `accepted` ровно на один шаг: Meaning Check обязан быть
именно `passed`.

## Поведение и границы

- **Поведение не меняется.** Порядок важности попыток сохранён дословно: копия
  Snippet хуже искажения исхода, искажение хуже потерянного Anchor, при равенстве
  побеждает более далёкая от Snippet (тай-брейк по `similarity`).
- **Заглушка (stub) остаётся вне кэша** не особым флагом `!stub`, а своим
  вердиктом: `meaningCheck: 'skipped'` не проходит `fitForCache`. С появлением
  ключа генерация происходит по-настоящему.
- **`similarity` не хранится в Rewrite.** Она нужна лишь для тай-брейка при выборе
  лучшей попытки и в решение о кэше не входит; `verdictOfRewrite` (мост от
  записи к вердикту для кэша) ставит `similarity: 0` — `fitForCache` его не читает.
- Прежний тай-брейк между двумя провальными по Meaning Check попытками стал
  единообразным: раньше двойное обновление `best` в паре с мутацией попытки
  на месте промотировало более позднюю попытку раньше честного сравнения по
  `similarity`. Теперь `best` обновляется один раз финальным вердиктом, и
  документированное правило «дальше от Snippet побеждает» соблюдается всегда.
