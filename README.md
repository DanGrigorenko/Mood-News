# Mood News

Читалка реальных новостей в разных эмоциональных регистрах. Факты неизменны,
меняется только тон. Смысл проекта — в [`CONTEXT.md`](./CONTEXT.md) и
[`docs/adr/`](./docs/adr/).

Сервер тянет реальные новости из RSS-лент (Ingest) и переписывает их под
выбранный Mood через LLM, сохраняя факты. Читатель выбирает Mood в выпуске и по
клику на новость попадает на её страницу, где оригинал и переписанная версия
стоят рядом — со ссылкой на источник и результатом Fact Check.

Интерфейс сделан как нотная партитура: настроение — это указание исполнения над
строкой, оригинал и переписанное — два стана, соединённых акколадой, а Fact
Check рисуется нотами и паузами.

## Откуда берутся новости

Ingest забирает Article из русскоязычных RSS-лент — **Коммерсантъ, РИА Новости,
Интерфакс** (список в `server/src/ingest.ts`). Лента отдаёт только Snippet
(заголовок плюс одно-два предложения анонса), поэтому Ingest идёт на страницу
каждой публикации и забирает **полный текст статьи** — он и хранится как Snippet
([ADR 0006](./docs/adr/0006-full-text-from-source-pages.md), пересматривает
[ADR 0004](./docs/adr/0004-snippet-only-no-page-scraping.md)).

Правило «нет полного текста — нет новости»: если текст статьи достать не удалось
(заглушка, недоступная страница, подозрительно короткий обрывок), новость в базу
не попадает — огрызков быть не должно. Каждый источник парсится по адресному
правилу своей вёрстки (`server/src/article-text.ts`); реклама, меню, навигация и
блоки «читайте также» в текст не идут. ТАСС и Lenta.ru убраны — их страницы
закрыты антиботом.

Ingest запускается автоматически при старте, если база пуста, и повторно —
кнопкой «Обновить» на странице. Ответ `POST /api/ingest` показывает, сколько
новостей добавлено и сколько пропущено из-за недоступного текста. Дедупликация по
ссылке: повторный Ingest уже известной публикации ничего не добавляет. Заход на
страницу — по запросу на новость, так что Ingest заметно дольше и сообщает ход
работы; падение одной ленты или одной страницы не роняет остальные.

## Хранение

SQLite файлом (`node:sqlite`, без ORM и миграций). Схема создаётся одним
`CREATE TABLE IF NOT EXISTS` при старте, ссылка — PRIMARY KEY (на нём и держится
дедупликация). Путь к файлу — `DB_PATH` (по умолчанию `server/mood-news.db`);
данные переживают перезапуск сервера.

SQLite, а не Postgres, выбран намеренно: проверяющему не нужно поднимать docker
или сервер БД — база это один файл, который создаётся сам при первом запуске.

## Переписывание тона (Rewrite)

`GET /api/articles/:id?mood=X` (где `:id` — `encodeURIComponent` ссылки Article)
возвращает переписанные заголовок и тело плюс результат Fact Check: список
Anchor, их число, список Missing Anchor, число попыток и исход Meaning Check
(`meaningCheck`: `passed`/`failed`/`skipped` и `distortion`). `GET /api/moods`
отдаёт пять доступных Mood (`neutral`, `joyful`, `sad`, `ironic`, `dramatic`) с
человеческими названиями. Произвольный Mood отклоняется, а не уходит в модель.

Пара «Article + Mood» — первичный ключ таблицы `rewrites`: генерация ленивая,
кэш вечный ([ADR 0001](./docs/adr/0001-lazy-rewrites-cached-forever.md)). Но в
кэш пишется только прошедшее обе сверки: провалившийся Rewrite отдаётся читателю,
но не кэшируется и генерится заново при следующем открытии
([ADR 0008](./docs/adr/0008-failed-rewrite-is-retried-not-displayed.md)). Первый
запрос пары медленный (вызов модели), повторный читается из базы и переживает
перезапуск.

### Как контролируются факты

Контроль двухступенчатый: детерминированная Anchor-сверка, а следом — смысловая
сверка вторым проходом.

**Ступень 1 — Anchor-сверка (детерминированная).** Из Snippet механически, до
всякой модели, извлекаются Anchor — числа, даты, суммы, цитаты и имена
([ADR 0002](./docs/adr/0002-deterministic-anchor-fact-check.md)). Промпт кладёт
их явным списком, требует сохранить дословно и писать числа цифрами, а не
прописью. После генерации Fact Check сверяет присутствие каждого Anchor в
объединении заголовка и тела. При потере — ретрай с названием потерянного.

Сверка детерминированная (сравнение подстрок), а не через модель-судью: судья
сам может галлюцинировать, стоит денег на каждую проверку и даёт разный ответ на
один вход. Регулярки и `String.includes` — воспроизводимы, бесплатны и
проверяются юнит-тестами без сети и без ключа.

**Ступень 2 — Meaning Check (второй проход модели).** Anchor-сверка ловит
пропажу и подмену Anchor, но не ловит переворот исхода события (Outcome) при
дословно сохранённых числах: «рабочий погиб» может стать «рабочий успешно
завершил проект», а Fact Check отчитается «факты сохранены: 1/1». Поэтому после
того, как Rewrite прошёл Anchor-сверку, второй вызов модели сверяет его с исходным
Snippet на сохранность Outcome — направления, результата и субъекта — и на
дорисованные факты, но не по тону (смена эмоциональной окраски — законная задача
Rewrite). Найденное искажение (Distortion) называется и уходит в тот же цикл
ретраев ([ADR 0005](./docs/adr/0005-second-pass-meaning-review.md)). Сам Outcome
защищён и правилом промпта переписывания
([ADR 0007](./docs/adr/0007-outcome-is-immutable.md)): Mood — это позиция
рассказчика, а не переоценка события.

Это осознанный пересмотр ADR-0002, где второй проход был отклонён как
недетерминированный и вдвое более дорогой: аргументы верны, но цена пропущенного
искажения исхода оказалась выше. Второй вызов платится один раз на пару
«Article + Mood» — кэш вечный. Сбой Meaning Check не роняет запрос:
Anchor-валидный Rewrite отдаётся с честной пометкой «сверка не проведена»
(`skipped`), а не выдаётся за пройденную.

**Провал не показывается и не кэшируется.** Если после всех попыток осталась
потеря Anchor, совпадение со Snippet или неустранённое искажение, Rewrite всё
равно отдаётся читателю — лучшая (последняя валидная) попытка, а не 500 и не
откат на Snippet. Но в кэш он не пишется и при следующем открытии генерится
заново, а под текстом больше нет абзаца о промахе: результат сверок решает судьбу
Rewrite, а не его вёрстку
([ADR 0008](./docs/adr/0008-failed-rewrite-is-retried-not-displayed.md)). На
экране остаются сводка Fact Check и нотный стан с Anchor — утверждение о
сохранности, а не извинение. Состояния сверок (`unchanged`, `meaningCheck`,
`distortion`) остаются в ответе API для eval и отладки.

### Замер качества промпта (eval)

Правку промпта отличает от везения замер. `npm run eval --prefix server` гоняет
замороженный корпус из 10 Snippet × 5 Mood (`server/eval/corpus.json`) против
живой модели, печатает все 50 Rewrite целиком и сводку против планки: 50/50 по
Missing Anchor, 50/50 по `unchanged`, не ниже 48/50 по Meaning Check
(детерминированные проверки — абсолют, недетерминированный судья — с допуском на
шум). Команда стоит денег и недетерминирована, поэтому в `npm test` не входит и в
CI не висит. Агрегация вынесена в чистую функцию (`server/eval/aggregate.ts`) и
покрыта тестами; сам раннер ходит в сеть и сам является проверкой.

#### Пример сработавшего ретрая

Реальная новость Коммерсанта (Ingest 2026-08-16). Модель в драматичном регистре
в первой попытке теряет число `56` («десятки пожарных»), Fact Check это ловит и
называет потерю в промпте, вторая попытка возвращает `56` — Rewrite проходит:

```
Article: https://www.kommersant.ru/doc/8890654
Anchor (8): «56», «14», «Wildberries», «Подольске», «WB», «Григорий», «Артамонов», «Telegram»

попытка 1:
  заголовок: Огненный ад под Подольском: склад Wildberries (WB) охвачен пламенем
  Fact Check: потеряно «56» → ретрай
попытка 2 (промпт требует вернуть потерянное):
  заголовок: Огненный ад под Подольском: 56 пожарных бьются со стихией на складе Wildberries (WB)
  Fact Check: все Anchor на месте → успех

Итог: attempts=2, anchorCount=8, missing=[]
```

Прогон воспроизводится командой `node .sandcastle/retry-demo.ts`. Цикл
`generateRewrite`, извлечение Anchor и Fact Check — настоящие
(`server/src/{rewrite,anchor}.ts`); ответы модели в этом прогоне заскриптованы,
чтобы потеря Anchor случилась детерминированно (живая модель теряет их редко и
непредсказуемо).

### Что использовали из AI (модель и конфигурация)

AI используется ровно в одном месте — переписывание тона в `Rewrite`: текст
Snippet отдаётся LLM (по умолчанию `glm-4.7-flash` от z.ai) с промптом, который
задаёт эмоциональный регистр и жёсткие правила сохранности фактов. Извлечение
Anchor, Fact Check, Ingest и хранение — обычный детерминированный код без
модели. Проверено на живом z.ai; ключ бесплатный (см. [`.env.example`](./.env.example)).

Обращение к модели — по OpenAI-совместимому HTTP. Три переменные в `.env`
(`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) переключают z.ai/GLM, OpenRouter или
Groq. Сервер читает `.env` из корня встроенным флагом Node
`--env-file-if-exists=../.env` — без пакета dotenv. Шаблон — [`.env.example`](./.env.example).

**Без `LLM_API_KEY`** эндпоинт работает на заглушке: Snippet отдаётся
механически, помечен `stub: true` и не попадает в кэш — с появлением ключа
генерация происходит по-настоящему. Заглушка не трогает факты, поэтому проходит
Fact Check.

## Структура

Два независимых пакета без workspaces, оркестрация — через `concurrently`:

- `server/` — HTTP API на [Hono](https://hono.dev). Предъявляется как отдельный
  сервис, не завязанный на фронт.
- `web/` — React + TypeScript на [Vite](https://vitejs.dev). Запросы к `/api`
  Vite проксирует на сервер, поэтому в коде фронта нет абсолютных URL с портом.

## Запуск

```bash
npm install   # ставит и корень, и оба пакета (server, web)
npm run dev    # поднимает сервер (:8787) и фронт (:5173) одной командой
```

Открой http://localhost:5173 — в выпуске без единого клика появятся реальные
новости (при первом старте сервер дожидается Ingest, это несколько секунд).
У каждой новости свой адрес (`?n=<ссылка Article>`), так что на неё можно дать
прямую ссылку.

## Проверки

Каждый тикет обязан прогнать их перед коммитом:

```bash
npm run typecheck   # tsc --noEmit в обоих пакетах
npm test            # node:test в обоих пакетах (без Vitest/Jest)
```
